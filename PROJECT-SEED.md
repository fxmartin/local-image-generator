## Objective

A CLI application to generate images locally with Qwen-Image-2.1, no cloud
required. Inspired by the Medium article "Qwen-Image-2.1 turned my two little
computers into an art department, no cloud required"
(https://medium.com/generative-ai/qwen-image-2-1-turned-my-two-little-computers-into-an-art-department-no-cloud-required-29494e26f340).
The CLI must run the model on the local machine and must also be able to call a
remote engine running on another of the developer's machines (e.g. the M3 Max),
so a small laptop can use a bigger box as its render farm.

## Tech Stack

- **Language**: Python 3.12+
- **Framework**: Typer (CLI), Rich (output)
- **Runtime**: CPython via `uv`
- **Inference backends** (pluggable, both from day one):
  - MLX port of Qwen-Image-2.1 on Apple Silicon (M3 Max, M1 Pro home-lab)
  - stable-diffusion.cpp with GGUF quantizations (Q4_K_M ~4.6 GB recommended)
    for cross-platform use, including the Dell XPS 13 (Intel Arc 130V/140V iGPU,
    30 GB RAM, no NVIDIA)
  - Remote: HTTP client to a daemon exposing one of the above on another host

## Architecture

CLI tool. Backend protocol abstraction with three implementations (mlx, sdcpp,
remote). An optional `serve` subcommand exposes a local backend over HTTP for
other machines on the tailnet.

## Notes

- Model management is a first-class feature: download, cache, verify checksums,
  list and switch quantizations from the CLI. Resolve Hugging Face models through
  `model-shelf` where it is available (macOS only).
- Remote execution is a core requirement: the CLI targets either a local backend
  or a remote engine (e.g. `--host m3max`), selected by config or flag.
- Qwen-Image-2.1 (released 2026-09-20) is a 7B model doing generation, editing
  and transparent-image output in one checkpoint. Reference VRAM: ~11 GB with
  GGUF, ~24 GB with INT8/FP8. Text encoder can be offloaded to system RAM at
  little speed cost.
- From the article (ASUS GX10, NVIDIA GB10, ~121 GiB unified memory):
  - Author's baseline params: 40 steps, guidance 1, seed 42. A larger output
    size yields a new composition, not an upscale.
  - BF16: ~52 s per 1K image, ~4 min at native 2K, ~72 GiB peak system memory.
  - GGUF recipe: Q4 transformer + official Q8 text encoder + tiled decoding,
    ~21 GiB peak; softer output, occasional small artifacts.
  - Qwen ships a separate prompt-rewriter model that expands prompts before
    generation; it improved composition but cost ~3 extra minutes. Reusing a
    saved expanded prompt is cheaper than re-running the rewriter.
  - Editing (e.g. recolor one object) at 1K altered unrelated textures; 2K was
    cleaner. Expect edit quality to be resolution-sensitive.
  - Remote pattern that works: a chat/agent on one box calls an image worker on
    another box over the LAN; the worker process exits after each job and frees
    its memory; both run fully offline once weights are cached. This is the
    shape the `serve` daemon and `remote` backend should follow.
- Machines: `macbook-pro-m3-max` (macOS), `home-lab` M1 Pro (macOS), `omarchy-xps13`
  (Arch Linux / Wayland). Never assume a platform; `uname -s` first.
- Tests run in local GitLab CI containers (Linux/arm64, root, offline): no test
  may download weights or reach the network; use fakes for backends.
